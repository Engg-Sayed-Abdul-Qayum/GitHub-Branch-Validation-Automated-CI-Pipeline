# WhatsApp Testing CI Lab

A learning project that combines a WhatsApp Web-inspired frontend prototype with a Jenkins-based Continuous Integration (CI) workflow. It is intended for practicing frontend development, Python code quality checks, automated tests, and pipeline automation.

> **Note:** This is an educational prototype, not an official WhatsApp product or a production messaging service. WhatsApp is a trademark of its respective owner.

## Project Goals

- Build a small WhatsApp Web-inspired interface using HTML, CSS, Tailwind CSS, and JavaScript.
- Keep frontend technologies in separate files to make the code easier to understand and maintain.
- Use GitHub to version and share code changes.
- Automate code-quality checks and tests with Jenkins.
- Publish test results from the pipeline when the configured JUnit report is available.

## Technology Stack

- **Frontend:** HTML, CSS, Tailwind CSS, JavaScript
- **CI automation:** Jenkins Pipeline (`jenkinsfile`)
- **Code quality:** Flake8
- **Automated testing:** pytest
- **Test reporting:** JUnit XML report (`reports/junit.xml`, when generated by the test command)
- **Source control:** Git and GitHub
- **Python environment:** `venv`

## CI Pipeline Overview

The Jenkins pipeline is designed to run the following checks:

1. **Checkout** — retrieves the source code from GitHub.
2. **Environment setup** — creates and uses a Python virtual environment.
3. **Dependency installation** — installs the packages listed in `requirements.txt` (including Flake8 and pytest, if listed there).
4. **Lint** — runs Flake8 against the Python application and test files, such as `app.py` and `test_app.py`.
5. **Test** — runs the automated tests with pytest.
6. **Report publishing** — publishes the JUnit XML report when the pipeline generates it.

A failed lint or test step should make the pipeline fail, helping catch issues before changes are accepted.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/Engg-Sayed-Abdul-Qayum/Whatsapp-Testing-CI-Lab-.git
cd Whatsapp-Testing-CI-Lab-
```

### 2. Create and activate a virtual environment

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

**Windows PowerShell:**

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `requirements.txt` does not yet include the CI tools, install them with:

```bash
pip install flake8 pytest
```

## Run the Checks Locally

Run Flake8 against the Python application and test files:

```bash
flake8 app.py test_app.py
```

Run the test suite:

```bash
pytest -v
```

If the project or Jenkinsfile configures JUnit output, generate the report with:

```bash
mkdir -p reports
pytest -v --junitxml=reports/junit.xml
```

The report is useful for Jenkins test-result publishing. If your `jenkinsfile` already defines a different command or report path, use that configured path consistently.

## View the Frontend

## Jenkins Setup

1. Configure a Jenkins Pipeline job for this repository.
2. Set the repository URL to the GitHub URL above and select the correct branch.
3. Set the pipeline script path to `jenkinsfile` if that is the exact filename in the repository. Jenkins paths are case-sensitive on Linux.
4. Ensure the Jenkins agent has Git, Python 3, and pip available.
5. Run the job and review the console output for checkout, dependency installation, lint, and test results.
6. Configure GitHub webhook delivery only if Jenkins is reachable from GitHub and the webhook endpoint is correctly configured.

Do not commit personal access tokens, passwords, private keys, or other secrets to the repository. Store credentials in Jenkins Credentials and reference them securely from the pipeline.

## Troubleshooting

- **`flake8: command not found`** — activate `.venv` and install dependencies using `pip install -r requirements.txt` or `pip install flake8`.
- **`pytest: command not found`** — activate `.venv` and install pytest.
- **No JUnit report found** — confirm pytest is invoked with `--junitxml=reports/junit.xml`, and that Jenkins publishes the same path.
- **Jenkins cannot trigger from GitHub** — verify the webhook URL, Jenkins reachability, job trigger configuration, and webhook delivery status in GitHub.
- **Frontend styles are missing** — check that the CSS file is linked correctly and that any Tailwind setup or generated stylesheet required by the project is available.
